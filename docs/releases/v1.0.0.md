# HOK Broadcast v1.0.0

发布日期：2026-10-08

v1.0.0 是 HOK Broadcast 的第一个公开正式版本目标，把此前分散验证的导播、延迟解说、OBS Overlay、Auto BP、Player ID 自动排序、BP Simulator、最终阵容、备份恢复和赛后 MVP 基础链路整理成一套可用于社区赛事的工作流。

> **重要：局内 Game HUD 仍为 Experimental / 测试功能。** 它已能在 OBS 中显示系列赛信息、人头、推塔与中立资源，但自动读取真实游戏 HUD、赛事机长时间稳定性和正式比分兜底尚未完成验收。正式比赛如启用 HUD，必须保留官方观战 UI、裁判记录或人工比分作为权威来源。

## 主要功能

### 导播、比赛状态与访问控制

- Control / Caster / Overlay 三端状态同步。
- BO1 / BO3 / BO5；Match BP（4 Ban）与 Normal BP（2 Ban）。
- Normal / Player / Global 三种跨局 BP 规则。
- 蓝/红先手、换边、比分、阶段、有效局历史。
- Undo、重置 BP、重置整场比赛。
- Caster 延迟数据时间线；延迟的是赛事数据，不是视频。
- 队伍资料库、首发、最多 20 名替补、照片与快速换人。
- 本机免登录；远程密码、Control/Caster/Overlay 独立 token 与 Overlay 登录页。
- Panel / Side 两种 Draft Overlay 布局。

### Auto BP

- 浏览器窗口采集。
- 蓝/红双方 4 Ban + 5 Pick，共 18 个独立识别框。
- 全屏精细校准与 18 框命名预设。
- Pick 双选 Turn。
- 普通 Pick 使用下一位对手预选变化确认上一轮结束。
- Pick→Ban 边界和最后一手使用行高亮恢复 fallback。
- Ban 圆形头像 mask、锁定 cue、空 Ban 保护与人工确认。
- Auto Watch 串行扫描，避免并发堆积。
- 自动锁定未触发时可用“手动确认当前最高候选”继续流程。
- 屏幕识别模式保留折叠式手动英雄选择器作为最终 fallback。
- Simulator 约 **1.5–2 秒**随机选角压力窗口下已能稳定完成 BP 识别；这是测试环境成绩，不是赛事机 SLA。

### P1–P5 Player ID 自动排序

- 复用 Auto BP 共享窗口，一次裁剪双方 10 个 Player ID。
- 默认 ID 区域从 Pick 头像旁推导；支持独立 10 区域命名预设，不覆盖英雄 18 框。
- 本地常驻英文/简中 Tesseract worker；不依赖比赛开始时联网加载模型。
- soft 快速 OCR；仅对未通过队伍追加 threshold 170/190 候选。
- 每队只在赛前已登记的 5 个 ID 中求 120 种全局一一映射。
- 双方可信时通过原子 action 一次更新 10 个槽位。
- UI 显示 roster-match confidence；原始 OCR confidence 保留为调试信息。
- 人工采用建议、手动交换与“恢复自动识别”。
- 同一排列连续两帧出现但弱槽位分散时，可合并两帧各槽位最佳匹配度；仍保持每槽 0.80、平均 0.90、margin 0.06 的安全线。
- 当前 Simulator 完整核查最佳实测约 **1.8 秒**；真实字体、缩放、OBS 并发与首帧时间仍需赛事机验证。

### 最终阵容与换英雄

- BP 历史与最终英雄归属分离。
- BP 完成后扫描 10 个 Pick 槽。
- 每队只在本队已 Pick 的 5 个英雄中求不重复最终分配。
- 稳定检测到英雄互换后自动同步。
- 支持“立即识别并应用换英雄”和人工下拉修正。
- Simulator 中“换英雄同步”与 BP 识别完全独立，可单独建立测试基线。

### BP Simulator

- 独立控制页与干净采集页。
- 三种互不混淆的测试：**BP 识别 / 换英雄同步 / Player ID 排序**。
- Match / Normal BP、蓝/红先手、圆形 Ban、空 Ban、双 Pick。
- 自动脚本支持最短/最长等待、随机切换预选英雄、最终稳定窗口与可调锁定 cue。
- Pick 头像 48–104px、Ban 位 24–64px 可实时调节并持久化。
- Player ID 模式会随机双方队内顺序并自动计时。
- Windows 一键后台启动与停止脚本。

### 英雄数据与图片

- Hero Data Synchronizer 持续维护当前英雄池。
- 已加入 Wang Wei / 王维（本地 ID 120，Camp ID 138）；新英雄同步在辅助详情页 5xx 时可使用官方 HOK 身份与 Key Art 兜底。
- 中英文、alias 与搜索。
- 英雄图片/数据运行时 override。
- 可搜索头像网格编辑器。
- Panel / Side 图片裁切与预览；现场保存写入 `data/match.json`，可用 `hero:crop-sync` / `sync-hero-crops.bat` 提升为 Git 跟踪的公共裁切默认值。
- Flowborn 形态合并/独立规则。

### 备份与恢复

- 数据变化后自动备份，保留最近 20 份。
- SHA-256 / 路径 / 大小校验。
- 停止后端后的完整恢复与比赛导入。
- 比赛导出排除访问凭据；完整备份包含本机访问配置。
- 单后端进程锁与有界操作日志。
- Control 可查看备份状态、立即备份和导出比赛。

### 赛后数据与 MVP

- 有效局固定十人身份、英雄与照片。
- 可按总览/生存/输出/团队等页面手动选择字段并批量 OCR。
- 保存字段来源、置信度与原始裁剪证据。
- 人工修正确认不会被低置信度 OCR 覆盖。
- MVP 由语音频道投票或赛事方人工决定；系统**不自动评判 MVP**。
- `/overlay/mvp` 使用统一蓝/红模板展示选中的 MVP。
- 自动判页、稳定画面检测与真实游戏全部结算页覆盖仍属于后续验收。

### Experimental：局内 Game HUD

`/overlay/game-hud` 已实现：

- 双方队伍身份与 Logo；
- 系列赛大比分；
- 当前 Game / BO / Stage；
- 当前小局人头、推塔；
- 最多六类可配置中立资源；
- 简约 / 完整密度；
- Undo、刷新/重连恢复、下一局计数重置。

**v1.0.0 中 HUD 仍标记为 Experimental。** 当前局内统计主要由 Control 人工维护，自动读取真实游戏 HUD 尚未实现；真实 OBS 长时间运行、不同游戏 UI 版本、误操作恢复和最终视觉遮挡仍需赛事现场验证。

## 性能与稳定性

- 各角色快照缓存与延迟事件二分查询。
- 英雄识别减少中间图片编码、重复裁剪与重复画面计算。
- 完全相同画面证据缓存。
- 重型编辑器与 Simulator 按需加载。
- Overlay / Simulator 使用固定设计画布并随窗口等比缩放。
- Player ID OCR worker 在后端启动时预加载并常驻。
- Player ID 首轮 fast path、按队追加候选、100ms 后台复核调度，同一时间最多一个 OCR 请求。
- CI 已覆盖英雄数据校验、生产 Build、服务器/单元测试与 ESLint；真实 HOK、OBS 和 Windows 赛事机仍需现场 smoke test。

## 推荐发布前彩排

1. 使用 BP Simulator 完整跑一轮 Match BP。
2. 将随机选角压到约 1.5–2 秒，确认 Auto BP 仍稳定。
3. 运行 Player ID 队内乱序测试，确认双方顺序自动同步；再测一次人工采用和恢复自动。
4. 校准真实游戏的 18 个英雄框和 10 个 ID 区域并分别保存预设。
5. 测试双 Pick、空 Ban、Pick→Ban、最后一手和至少一次换英雄。
6. 检查 Draft Overlay、Caster 延迟与断线重连。
7. 停止/重启后端，检查比赛状态与备份恢复。
8. 如果启用 Game HUD，仅作为 Experimental 功能单独彩排，并保留人工/官方比分兜底。
9. 如果启用 MVP 页面，至少跑一次结算页 OCR + 人工修正 + 蓝/红两种 MVP 卡片。
10. 真实 OBS 录制至少跑一段持续测试，重点检查此前出现过的音画不同步/停止录制问题。

## 已知边界

- 图像识别依赖实际游戏 UI、头像裁切、亮度、缩放和版本；游戏更新可能需要重新校准。
- Player ID 最佳约 1.8 秒和 BP 1.5–2 秒压力成绩来自当前 Simulator/测试环境，不是所有硬件的保证。
- ID 区域与 18 框预设保存在 Director 浏览器 localStorage，不会自动跨电脑同步。
- 日文等额外 Player ID 语言需要对应 Tesseract traineddata。
- Game HUD 仍是测试功能，自动 HUD 读取未实现。
- 赛后 MVP 自动判页/全结算页覆盖未完成。
- Caster 延迟是数据延迟，不是视频平台延迟。
- Cloudflare Quick Tunnel 地址每次启动可能变化。
- 固定域名 Docker/Caddy 配置已预留，但尚未作为 v1.0.0 的已验收托管环境。
- OBS、直播平台、远程解说和 Discord 的完整端到端音画同步仍需要赛事现场彩排。

- Wang Wei 当前使用官方 HERO DATA 肖像 + 专用近景 `iconCrop` 作为临时方形头像，外圈装饰被裁掉；横向 Key Art 仅供 Panel / Side，Auto BP 识别模板也与 UI 头像用途分离。Hero Sync 后续取得稳定 Icon 时会自动转为本地 `/heroesImg` 资源。

## 推荐环境

- Windows 10/11
- Node.js 24
- Microsoft Edge 或 Google Chrome
- OBS Studio
- cloudflared（需要 Quick Tunnel 时）

## 从开发版本升级

1. 拉取 v1.0.0 对应 tag / Release Source；
2. 在 `vite-project/` 运行 `npm ci`；
3. 运行 `npm run build`；
4. 重启 Broadcast；
5. 刷新 Director / Caster / OBS Browser Source；
6. **保留并备份 `vite-project/data/`**；
7. 重新检查 Auto BP 18 框与 Player ID 10 区域预设；
8. 如浏览器 profile/localStorage 被清理，重新载入或校准本机预设。

不要把旧版本的 `node_modules` 当作发布包的一部分。
